# 工作区文件契约与模板

新主题开练时按此创建文件。每次练习后必须更新（教练的"记忆"），否则下次拆解失真。

## 目录结构

```
<项目>-刻意练习/
├── README.md                  # 使用说明 + 输入资料清单
├── plan/
│   ├── 长期学习计划.md         # 阶段化总计划（含里程碑 + DoD）
│   ├── 知识地图.md             # 知识点拓扑 + 心智模型清单 + 概念状态索引 + 类比脚手架
│   └── 每日任务清单.md         # 日粒度任务 + 打卡（可选，长期项目用）
├── goals/goal-log.md          # 目标拆解历史（i+1 依据 + DoD + 结果）
├── sessions/                  # 会话记录（YYYYMMDD-主题.md）
├── errors/error-log.md        # 错误账本
├── feedback/feedback-log.md   # 评估 + 学习集合/目标调整记录
├── heatmap/掌握热力图.md      # 🟢🟡🔴 状态 + next_review + 更新日志
├── heatmap/基线评估.md        # 子能力 1-10 分基线（可选，每月更新）
├── concepts/                  # 概念卡（按需外挂，有故事才建档；见「概念卡」节）
└── templates/                 # 下列模板
```

## goal-brief 模板（能力二输出）

```markdown
### L-00X ｜ 主题（当前）
| 字段 | 内容 |
|------|------|
| 日期 | |
| 阶段/单元 | 阶段 X · L-00X（如拆多场，标「场 1/N」） |
| **goal 类型** | normal（默认，常规）/ tutorial（教程关·跑通系统最小闭环）/ boss（综合关·组合前置 goal 技能，无新知识点） |
| **i+1 依据** | 为什么刚好超出当前能力（历史/热力图证据） |
| 历史状态 | |
| **前置知识链** | 依赖哪些前置知识点；缺失则先补前置再进目标 |
| **概念引用清单（含热力图状态 + 用途三态）** | 本次将引用的所有概念/术语 + 🟢🟡🔴 + 用途：已学 / 新概念·铺路（标注+够用抽象，不入考核）/ 新知识点·本课要学（教学+验证）；🔴 概念进 DoD 时必须为第三态 |
| **范围覆盖矩阵（强制）** | goal 名义范围内的全部知识点逐条标注三态：① 本 goal 覆盖（挂 DoD）／② 延后（注明拆到哪个 goal）／③ 仅铺垫（钩子）；**不允许无标注消失**。自检：goal 标题范围 = DoD 覆盖范围，不一致就收缩标题或补 DoD。**来源纪律**：知识点来自知识地图已有清单 + 课时标题一次性录入，**禁止为填矩阵全量读讲义/PDF/WebFetch**（token 优化 · v1.2.7） |
| **心智模型目标** | 本 goal 要显式建立的 ≥1 个流程/串联心智（动词类） |
| **障碍预判（陷阱预告）** | 预判 ≥2 个执行障碍（时间/动机/环境/概念卡点）+ 应对方案；每个障碍补「卡住=情报点 X」（踩中即获得：识别信号 / 触发规则化预警）。格式：障碍 → 应对 → 卡住后拿到什么 |
| 目标（单一） | |
| 边界（不做） | |
| 讲义/资料锚点 | |
| 可验证标准（DoD） | ①②③④ |
| **练习步骤（按序，每步含时长）** | ①→②→③→④（完成一步勾一步；被打断时记录断点） |
| 练习方法 | |
| 练习路径 A/B（可选） | 同 DoD 下给 2 条路径供学习者开工时选（如「复现驱动 or 找茬验证」）；无法拆分不填。选择权只给「怎么练」，不碰「练不练 / DoD 判定」 |
| 预计时长 | |
| 结果 | （回填：达标情况 + **难度体感 太难/刚好/太简单**——由每场「挑战度」累积，供 IRT 趋势层校准） |
| 调整 | （回填） |
```

## 错误日志分类

| 分类 | 含义 | 处理 |
|------|------|------|
| E-ENV | 环境类（Docker/端口/依赖） | 记录复现步骤与解决命令；同错误 ≥2 次 → 升级 checklist |
| E-CON | 概念类（易混概念/机制误解） | 补概念讲解 + 费曼复述 |
| E-CODE | 代码类（bug/类型错误） | diff 对比 + 自纠练习 |
| E-DESIGN | 设计决策类（为什么这样设计） | 记录决策依据，练"讲清为什么" |
| E-COACH | 教练自身失误（双向纠错） | 立即修正并记录 |

每条遵循四段式：定位 → 归因 → 修正 → 迁移。

记录语义 = **情报入账**（错误=情报 · 2026-09-09）：踩坑是有价值的信息事件（第一次踩 = 拿到免疫），不是事故。**防再犯纪律不变**：同坑 ≥2 次 → 升级规则区（trigger/validation）。踩第一次=情报，第二次=问题。

## 错误规则化（复发错误 → 可复用规则）

四段式记录的是「这一次怎么错的」；当同一错误**复发（≥2 次）或属模式性错误**（E-COACH 教训类）时，升级为「可复用规则」，在四段式之外补两个字段：

| 字段 | 含义 | 例 |
|------|------|---------------------------|
| trigger（触发边界） | 什么信号/情境下会再犯 | 改了文件名/shell/命令，却没同步改 pattern/const 等值 |
| validation（自查项） | 开工前/提交前怎么自查 | 改任何命名后，grep 一遍同义 pattern/const/引用是否同步 |

规则三个消费点：① 喂 goal-brief「障碍预判」（拆目标直接取，不现想）② 练习前预警（教练按 trigger 检查当前 goal 是否命中）③ 挂概念卡 links（这知识点易栽在哪）。

错误账本分两区：**一次性错误**（只留四段式）+ **规则区**（复发错误，带 trigger/validation）。

## 知识地图格式（能力一产出）

```markdown
# <主题> 知识地图
## 一、知识点拓扑（名词：是什么）
| 簇 | 知识点 | 核心概念 | 源码/文档入口 |
## 二、心智模型清单（动词：怎么串起来）★ 每阶段 ≥2 个
| 阶段 | 心智模型/流程 | 组成知识点 | 验证方式（链路重述/走通） |
## 三、概念状态索引（引用前查这里）
| 概念/术语 | 状态 | 首次引用课次 | 备注 |
## 四、待解锁区（🔒 前瞻 · 好奇驱动）
| 未来概念（灰显/锁定语义，只给名称、不展开内容） | 预计解锁课次 |
```

待解锁区规则（2026-09-09）：只给名称不展开（受「点到为止」约束，展示 ≠ 展开）；来源 = 计划中后续课的标题级概念一次性录入，禁止为填此区全量读讲义/文档；更新节奏 = 每拆 1 goal / 每课推进时，已解锁条目移入「一、知识点拓扑」，新条目从计划补入（保持 ≤ 未来 1-2 课）。

## 概念卡（按需外挂 · 方案 C · OKF 思想）

「有故事」的知识点 / 心智模型 / 错误才外挂一张卡，存 `concepts/<slug>.md`（slug = 稳定键，全项目唯一）。无故事的概念留在知识地图 / 热力图的索引表里，不产生文件（增量更新，反全量扫描）。

**何时建档**（满足任一）：① 踩过坑 / 回炉过 ② 反复出错 ③ 需挂验证证据链 ④ 心智模型（动词类，默认建档）。

**字段契约**（借 Google OKF 语义，不自称 OKF）：

```yaml
---
slug: plan-flow            # 稳定键：键控引用，替代位置引用
type: 心智模型             # 知识点 / 心智模型 / 错误
status: 已学               # 三态：已学 / 钩子 / 延后
resource: docs/...         # 溯源：讲义 / commit / 文档路径，1:1 精确指向
verified:                  # 验证事件 → 掌握度由它推导，不手填
  - by: "换场景题 5/5"      # 验证方式必须是「独立产出」
    at: "2026-09-05"
next_review: "2026-09-12"  # 绝对日期（Ebbinghaus 序列落地，非相对 TTL）
links:                     # 互链：断链容忍 = 钩子（可指向未建档概念）
  - ../concepts/concept-b.md
---
```

**掌握度推导**（治 E-COACH-003/004 判定虚高）：🟢🟡🔴 不手填，由 `verified` 事件推导——🔴 无验证或验证失败；🟡 仅 1 次验证通过或证据不足；🟢 **≥2 次不同场景**独立产出验证通过（换场景题 / 链路重述 / 独立演示）。教练只记事件，状态算出（证据计数 · 借鉴 BKT：单次答对不足以排除猜测）。无卡知识点仍在热力图手填，作为过渡。

**引用纪律**：跨文件引用一律用 `slug`（键控），不用位置 / 行号——重排不丢引用。
