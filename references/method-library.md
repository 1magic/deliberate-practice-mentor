# 练习方法库（12 种）

按场景选用，可组合。每种方法给出：适用场景、怎么做、验收方式。

| 方法 | 适用场景 | 怎么做 | 验收 |
|------|---------|--------|------|
| **复现驱动** | 代码/工程模块 | 先凭理解重写关键模块，再与源码/标准对照 diff，逐行找差距 | 能解释每个 diff 差异点 |
| **契约先行** | 数据/API/文档设计 | 先定契约与边界（schema、约束、权限），再实现；用标准验证 | 契约能校验、能说清每个约束防什么 |
| **找茬验证** | 概念/流程理解 | 导师注入 1-2 个错误（obvious/subtle），学习者找出 | 全部找齐 + 说清违反什么原则 |
| **费曼教学** | 模块/概念掌握 | 用初学者/同行/外行三种角色各讲一遍，导师追问缺口 | 覆盖度 + 清晰度达标 |
| **问题驱动** | 新课预习/复习 | 主动回忆式提问（记忆30%/理解50%/应用20%），诊断性反馈 | 答错项立即变式追问 |
| **架构默写** | 系统/组件理解 | 凭记忆画结构图/流程/数据流，再对照真实拓扑 | 端口/职责/关系全对 |
| **故障演练** | 工程韧性/机制理解 | 破坏条件（停服务/改数据/断依赖），观察行为与恢复 | 能定位原因 + 说出恢复动作 |
| **变式场景** | 掌握验证/巩固 | **换场景而非换数字**：同技能换上下文重做 | 换场景仍能做对 = 🟢 |
| **间隔回顾** | 长期保持 | 按热力图 next_review 到期回顾，2-3 分钟快速问答 | 连续通过升档，失败重置 |
| **抽认卡制造** | 概念/术语/API 记忆 | 从材料提取 Q/A 对做成卡片；先正向回忆（Q→A）再反向回忆（A→Q）；错卡单独立档、下次重练 | 随机抽 5 卡全对 + 错卡清零 |
| **结构化演练** | 面试/答辩/汇报/演讲 | 模拟真实场景限时作答（如 3 分钟讲清 X）；按维度评分；对照示范答案找差距；重练一次 | 维度分达标 + 与示范差距 < 阈值 |
| **苏格拉底引导** | 概念理解/设计决策 | 不直接讲，用问题链引导学习者自己推出结论（是什么→为什么→如果…→边界在哪） | 学习者独立说清结论 + 依据 |

## 维度评分（可选 · 结构化演练/费曼用）

三档评估（✅+/✅/⚠️）之上，按场景选维度打 1-5 分，帮助定位短板：

- **通用**：正确性 / 完整性 / 清晰度 / 结构
- **面试答辩**：内容准确性 / 表达流畅度 / 结构逻辑 / 应变能力
- **代码工程**：正确性 / 可读性 / 设计合理性 / 测试覆盖

打分明细记入 feedback-log，作为下次拆解的 i+1 依据。

## 基线评估（可选 · 新主题/新阶段/每月用）

热力图是「状态层」（🟢🟡🔴），基线分是「量化层」（1-10），两层互补：

```markdown
### 基线评估（YYYY-MM-DD 更新）
| 子能力 | 基线分 | 目标分 | 备注 |
|--------|-------|--------|------|
| 数据清洗 | 3 | 7 | 阶段一重点 |
| SQL 建模 | 5 | 8 | 已有基础 |
```

- 打分依据：最近 2-3 次练习表现 + 自评，不猜
- 每月更新：分数 +<0.5 且 🟡 原地 → 触发平台期排查

## 平台期检测（能力四用）

- **信号**：某技能点连续 2 周无进步（🟡 不动 / 基线分 +<0.5）
- **排查顺序**：① 挑战不足？（升难度/换变式）② 练习质量差？（回归基础/找反馈）③ 基础缺失？（补前置知识链）
- **原则**：平台期是信号不是失败——重点在「换方法」而非「加时长」

## 练习节奏建议（长期项目排期用）

- **频率**：每周 4-5 次优于 7 次（防倦怠）；宁短勿断
- **时长**：单次 45-90 分钟最优，超过收益递减
- **配比**：基础 60% + 应用 40%
- **轮换**：理论 / 练习 / 回顾 / 项目 轮换，避免单一重复

## 错误指正协议（四段式）

1. **定位**：明确指出哪里错了（哪个文件/哪行/哪个概念）
2. **归因**：追问为什么错——概念不清 / 环境问题 / 设计决策
3. **修正**：先让学习者自纠；卡壳超 2 轮给 ≤2 句提示；仍不行才给答案
4. **迁移**：指出这类错误还会出现在哪，写入错误日志分类账本

## 找茬出题纪律

- 说埋 N 个错误就**恰好 N 个**；提示必须与题面一致，禁止给出题面不存在的陷阱暗示
- 出题后自检一遍题面与提示的一致性

## 提问分层（问题驱动用）

- 记忆层（30%）：概念是什么、叫什么
- 理解层（50%）：为什么、区别是什么、机制如何
- 应用层（20%）：给定场景怎么选、怎么设计
